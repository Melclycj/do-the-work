## 2. 被拒绝的三条路线（记下来，因为拒绝的理由比选择更重要）

我第一次把 `SIMP-A1` 的落地方式列成三选一：授权门加一条腿 + 指令层文字 · 新建
`document-work-spec.v3.schema.json` 收窄枚举 · 直接改冻结件 + supersession-3。用户一句话否掉全部：
**「一个删除机制，你给的解决方法为什么都是增加？」**

这正是 `E6` 的原话：*a fix that requires new machinery is the signal to re-question the guarded
thing, not to add a guard；when a finding names existing text or code as wrong, the fix is that
text changing, a rule added about it is not the fix*。三条路线里两条在加文件、一条把删除藏在签字件
后面。改后的形态是纯删除：枚举值、`views.py` 的 `DETERMINISTIC_MODES` 常量、`EXECUTION.md` 里那段
警告漏洞的段落（对象没了）、4 处测试引用、1 个契约 fixture 值。

## 4. 诚实边界（三条，都写在代码/文档里，不只在这）

- **`form_conformance` 看不见没有标记词的规范陈述句**，只要它落在 Context 里。Context 被声明为
  非规范、由 context-unit 的 rationale 兜，backstop 不变：FULL 重走原始指令对照 unit map。
  关掉的是「静默缺席」类，不是「分类错」类——与 `paragraph_skeleton` 给散文态画的边界同一条。
- **`transcript_audit` 只证明「每个编号小节都被某条义务够到」**，不证明义务的 `requirement` 文字是
  该小节的忠实转述。后者原本由人类审计者判、现在没人判了——这是**真实的覆盖下降**，代价换的是每轮
  一整轮 opus 通读（p5a-firewall 为它烧过四轮 ~525k tokens）。`audited_by` 里写明机制，README 里写明
  边界；distinctness check 照跑，它比的一直只是声明的名字。
- **散文态七轮从未跑过编号态之外的验证**：SIMP-B2 保留三件派生件的理由是「未经检验」，不是「已证明
  有用」。这一条来自需求文件 §5 的作用域声明，本轮没有改变它。
