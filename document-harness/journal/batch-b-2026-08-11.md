## §3 `E2` 要不要加守卫 —— 三条实测（`HD-27` 的 basis）

**① 产品 run 侧 `E2` 已经有机器。** `_check_git_diff_boundary`（`checks.py:310`）把候选改动路径交给
`evaluate_boundary(changes, ctx.boundary)`，比的是 `write_scope` / `out`。p4-bridge 的
`effective_change_boundary.out` 逐条列着 `ResearchSystem/schema`、`…-v3.md`、`…-supersession-1.md`、
`…-supersession-2.md`。碰一下即 FAIL，模板末尾 `if not ok or passed != len(results) …` 拒绝推进状态。
**所以"`E2` 无机械 enforcement"只对构造批成立，不对产品 run 成立。**

**② 构造批那半边有独立评审兜着。** 每轮 FULL 的 boundary 检查明确点名 frozen surface——
`v3-review-full-11ce5b4.md` §5 原话 "the boundary — frozen surface, git discipline, budget, range,
instruction layer of the subject — holds"。要出事，须一次无裁决的冻结面写入同时躲过独立读者。

**③ 接线本身要先过 `E2`，而其增量价值已被 `HD-16` 吃掉。**

```
$ grep -c '"additionalProperties": false' schema/document-assurance-v3/*.json
（15 个文件全部 ≥1）
$ grep -rl "schema_pack_digest\|contract_digest" assurance/
(empty)
$ grep -n "pack_digests" tooling/rsclib/harness/resolver.py
272:        "bindings": {**schemas.pack_digests(), "resolver_version": resolver_version},
```

三条读法：(a) 15 个冻结 schema **全部** `additionalProperties: false`，故往证据文档加 `bindings`
字段 = 改冻结 schema = **先欠一次 `E2` 裁决**；(b) v3 证据里 `schema_pack_digest` /
`contract_digest` **一次都没出现**，而 v2 的 `resolver.py:272` 一直在记——所以 `pack_digests` 零调用
的真因是**v3 证据不记 interface 版本**，与 `E2` 缺守卫是两件事，被 rider `PD` 合并了；(c) digest
相对路径判据多出来的能力只有"证据离开本仓后仍能自证"，而 `HD-16` 刚裁了已关闭 run 的产物**不出仓**。

**另记一条读法差**：`E2` 的谓词是"有没有裁决"，digest 只看得见"字节变没变"。守卫拦下的是*变化*，
而 `E2` 允许有裁决的变化——它没把纪律变成机器，只是挪了个地方，外加要维护一份钉死的期望值
（第二份拷贝，`E3` 已咬过多次）。且清除通道若是 `--no-verify`，会顺手关掉 review-freeze 与
repo-audit——正是 rider `freeze-audit` 记过的互锁形状。
